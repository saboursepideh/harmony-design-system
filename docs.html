01 · Overview

Why Harmony exists

Before Harmony, our Figma "Design System" file was not something anyone could trust. Components were detached, the same button lived in several files with different looks, and nothing matched the Mantine components engineers actually ship. Harmony fixes that with one rule: if it isn't in Harmony, it doesn't exist.

1

One source of truth

Tokens are defined once and flow to Figma variables, CSS, Mantine theme, and the AI rules file. Nobody copies a hex code.

2

Built on what ships

Every component maps 1:1 to a Mantine component and prop. If design and code disagree, the system is broken, not the developer.

3

AI drafts, humans decide

AI generates tokens, variants, and docs from our brand rules. Design reviews and approves every change before it ships.

4

Clear over clever

IT admins scan risk under pressure. Status, risk, and priority always pair color with a word and an icon, never color alone.

Who uses Harmony

Three audiences, one system. Each reads it in the format that fits them.

Designers

Figma library with variables, variants, and boolean properties. Nothing detached, every instance linked.

Engineers

CSS tokens, a Mantine createTheme() file, and Code Connect snippets right inside Figma Dev Mode.

AI agents

A machine-readable rules file and DTCG token JSON, so Claude and Copilot build on-brand UI by default.

02 · AI workflow

How AI builds the system

I don't draw components by hand anymore. I give AI the brand guidelines, the Mantine theme, and the rules. It does the repetitive work: building variables, variants, documentation, and code mappings. I review every step and make the design decisions.

The rules file: how AI agents stay on brand

This file lives in the repo next to the code. When anyone, a designer, an engineer, or an AI agent, asks Claude or Copilot to build UI, it reads these rules first.

# harmony.rules.md · excerpt
## Tokens
- Never use raw hex values. Use semantic tokens: --text-*, --bg-*, --border-*, --status-*, --risk-*.
- Primitives (--teal-600, --ink-400...) are for building semantic tokens only.
- --text-disabled (#8F9CAE) fails AA. Use it for disabled text only. Placeholders use --text-secondary.
- Lime (#96C23A) is decorative. Never use it for text or as the only signal.

## Components
- Build with Mantine. Use Harmony wrappers: <RiskBadge level="high" score={71} />, not a custom span.
- Risk, status, and priority always pair color with a text label.
- Cards: radius --radius-lg (12px), padding --inset-card (20px), gap --gap-cards (12px).

## Typography
- Lexend only. Use the 12 --type-* styles. No other font sizes.
- Numbers in metrics use --type-metric-* with font-variant-numeric: tabular-nums.

How Harmony stays true

A design system only works if it stays the single source of truth. So adding or changing something follows one path, and AI checks the files every week for anything that drifted.

1 · Request
Anyone asks

Designer, engineer, or PM opens a request with the use case.

2 · Check
Does it exist?

AI searches Harmony for an existing component or variant first.

3 · Draft
AI drafts it

Variants, tokens, docs, and code mapping, from the rules file.

4 · Review
Design + Eng

I review the design; engineering reviews the Mantine mapping.

5 · Publish
Ship it

Library published, tokens versioned, changelog written by AI.

Weekly drift audit (AI)

Finds detached instances in product files
Flags raw hex values and off-scale font sizes
Compares Figma variables to orchestry-tokens.css
Re-checks every text pair for WCAG AA
Posts a short report for design and engineering

Versioning

MajorToken renamed or removed, component API changed
MinorNew component, variant, or token
PatchValue tweak, docs fix, contrast fix

Figma library, CSS tokens, Mantine theme, and the rules file always share one version number.
